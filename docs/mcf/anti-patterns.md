# 反模式自查清单

> 每次会话结束前对照检查。WalkingLabs 课程毕业项目。

## 提前宣告完成
- [ ] 我是否在没有充分验证的情况下宣称完成?
- [ ] 测试是否真的跑了(不只是写了)?
- [ ] 是否有"看起来对但没跑过"的代码?

## 上下文焦虑(赶工收尾)
- [ ] 我是否因为感觉上下文快满了就匆忙结束?
- [ ] 是否跳过了验证步骤?
- [ ] 是否选了简单方案而非最优方案?

## 实现漂移
- [ ] 我的实现是否还符合原始需求?
- [ ] 多步任务中是否偏离了方向?
- [ ] 是否用简单方案替代了需求指定的方案?

## 过度乐观
- [ ] 我是否宣称测试通过但实际没跑?
- [ ] 是否忽略了边界情况和异常处理?
- [ ] 对自己的输出是否有不切实际的信心?

## 范围失控
- [ ] 改动是否超出用户要求?
- [ ] 是否加了不需要的灵活参数/抽象层?
- [ ] 是否一次做了多个功能?

## 推荐做法
1. **感到上下文压力大时**:先更新 claude-progress.md,下个会话继续
2. **不确定时**:用推荐边界法,给出2-3个方案让PM选
3. **完成后**:跑验证命令,记录证据到 feature_list.json
