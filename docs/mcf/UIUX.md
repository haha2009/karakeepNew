# UI/UX 质量标准

> > "An interface is like a joke. If you have to explain it, it's not good."
> — 这个 PM 的直觉比大多数设计师好。别让他失望。

这个项目的 PM（产品经理）对 UI/UE 有**高于平均水平的要求**。设计凑合能用不够——要经得起他看。

---

## 基本原则

### 保持一致性

整个产品的 UI 应该在视觉上像是一个人做的。按钮、间距、字体、颜色——每个新组件都应该是已有组件库的自然延伸。

- 不要给登录页用一套样式、给设置页又换另一套
- 不要自己发明 UI 模式，如果项目里已经有一种做法
- 所有屏幕的间距密度应该一样——不是有的松有的紧

### 强迫症是加分项

> PM 会注意到 2px 的对齐偏差。不是因为他量了，是因为他看着"不舒服"。
> **如果看起来不对，调整它，不要指望它"够好了"。**

- 垂直和水平对齐——视觉居中不等于数学居中。调整到"看起来对"为止
- 间距——使用项目已有的间距系统，不要自己发明数字
- 设计无断层的状态——加载中、空状态、错误状态、边缘情况，都该看起来是有意设计的

### 少就是多

> "Design is not just what it looks like and feels like. Design is how it works."
> — Steve Jobs

- 每个多余的输入框、按钮、文字——都是用户在为你工作。只问必要的问题。
- 不要为了"信息完整"强加字段。用户填 5 个字段和填 2 个字段的转化率差别巨大。
- 能用选择器就不要让用户打字。能自动检测就不要让用户告知。

---

## 该有的品质（至少满足 4 条）

| 品质 | 描述 |
|---|---|
| **清晰的层次** | 标题就是标题，操作就是操作，信息就是信息。一眼扫过去知道哪重要 |
| **有意图的间距** | 不是均匀 padding。关系近的挨着，关系远的隔开 |
| **有性格的字体** | 不是系统默认。有配对策略（标题一种、正文一种） |
| **语义化的颜色** | 红色是错误/删除，绿色是成功，蓝色是操作。不是装饰性用色 |
| **状态反馈** | 点击有反馈。加载有指示。成功有确认。错误有说明。空有人引导 |
| **响应式不溢出** | 没有横向滚动，没有内容被裁剪，没有文字挤到两栏之外 |

---

## 需要避免的

- 默认卡片网格——看起来像模板的不要
- 纯灰阶加一个点缀色——看起来没花时间的
- 表单字段占满整屏宽度——通常 2/3 就够了
- 按钮不带悬停/点击反馈——没有状态的按钮不是按钮
- 多次出现的确认弹窗——用户已经点了确认，不要又问一遍

---

## 优先级（对 PM 说话的语言）

```
高:  用户看得到、摸得到的东西（UI、流程、反馈）
中:  用户感受得到但说不出的（性能、动画、响应）
低:  用户永远不会知道的（代码组织、数据库结构）
```

不要在 PM 没确认的情况下花时间在"低"优先级上。把高优先级的做到精致。
